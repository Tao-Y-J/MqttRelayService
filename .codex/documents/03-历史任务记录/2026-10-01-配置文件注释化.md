# 2026-10-01 配置文件注释化（appsettings 全量中文注释）

## 目标

配置项数量已经增长到运维无法凭键名判断用途的程度，需要让 `appsettings.json` / `appsettings.Development.json` 自身携带中文说明，运维打开配置文件即可知道每个键的作用、单位、默认值与取值范围。

## 实际实现

### 配置文件

- `src/MqttRelayService/appsettings.json` 与 `src/MqttRelayService/appsettings.Development.json` 为全部配置键补中文注释：每个键说明「作用 + 单位 + 取值/默认值 + 边界」，并按 `Service` / `Mqtt` / `Auth` / `Routing` / `Reliability` / `Web` / `AuditStorage` / `Serilog` 分节加 `// ===== 分节名 =====` 标题。
- 注释使用 `//` 行注释；`appsettings.Development.json` 顶部说明它与 `appsettings.json` 的加载与覆盖关系，并在与生产取值不同的键（`QueueCapacity`、`EnqueueTimeoutMs`、`MaxConcurrentHandlers`、`Serilog:RetentionDays`、`Serilog:IncludeCallerInfo`、`Serilog:MinimumLevel:Default`）后注明开发环境取值。
- 两个文件保持原有编码与换行：UTF-8 with BOM；`appsettings.json` 为 LF（同时补上文件末尾换行），`appsettings.Development.json` 为 CRLF。

### 安装/卸载脚本（必须同步改动）

- `.NET` 配置提供程序会跳过 `//` 与 `/* */` 注释，但 `Scripts/install-service.ps1`、`Scripts/uninstall-service.ps1` 用 Windows PowerShell 5.1 的 `ConvertFrom-Json` 读取 `Service:Name`、`Mqtt:TcpPort`、`Web:Port`、`Web:Enabled`，该解析器遇到注释直接抛错；异常被 `catch` 成 Warning 后回退默认值，表现为「配置改名不生效」而不报错。
- 两个脚本各新增一个 `Read-RelayJsonConfig`：先用正则 `'(?s)("(?:\\.|[^"\\])*")|(//[^\r\n]*)|(/\*.*?\*/)'` 剥离注释再交给 `ConvertFrom-Json`。字符串字面量分支放在最前且原样保留命中文本，`//` 出现在字符串内（`http://`、路径）时不会被误删。
- 两处调用点从 `Get-Content $configPath -Raw | ConvertFrom-Json` 改为 `Read-RelayJsonConfig -Path $configPath`。两份实现按仓库既有约定（`Get-RelayServiceNamesForCurrentDeployment` 同样是两份）保持脚本自包含。

### 测试

`tests/MqttRelayService.Tests/ConfigurationFileCompatibilityTests.cs`（新增，6 个用例）锁住三条契约：

1. `ShippedAppSettings_AfterCommentRemoval_ShouldBeStrictJson`：真实配置文件含 `//` 注释，且剥离注释后能被默认选项的 `JsonDocument.Parse` 解析——即不存在尾随逗号等 PS 5.1 `ConvertFrom-Json` 不接受的结构。
2. `ProductionAppSettings_ShouldBindAllSectionsAndPassStartupValidation`：用生产相同的方式（`ConfigurationBuilder` + `AddJsonFile`）加载真实 `appsettings.json`，逐节绑定 `ServiceOptions` / `MqttOptions` / `AuthOptions` / `RoutingOptions` / `ReliabilityOptions` / `WebOptions` / `AuditStorageOptions` 并断言取值，再调用 `Program.ValidateAuditStorageConfiguration` 确认真实配置能通过程序自身的启动校验；同时断言 `ShutdownDrainTimeoutMs >= RetryMaxDelayMs`、`MaxPendingRetryTasks <= QueueCapacity`、`MaxConcurrencyHardLimit >= MaxConcurrentHandlers` 这些跨键不变式。
3. `DevelopmentAppSettings_ShouldOverrideProductionValues` 与 `ServiceScripts_ShouldParseAppSettingsThroughCommentTolerantHelper`：前者断言环境文件确实覆盖生产取值并通过启动校验，后者断言两个脚本都通过 `Read-RelayJsonConfig` 读取配置、不再出现裸的 `Get-Content $configPath -Raw | ConvertFrom-Json`。

## 关键决策

- **注释直接写进 `appsettings.json`，而不是另建一份说明文档**：运维的目标是改配置时不必切换文件；.NET 配置提供程序原生支持注释，代价只落在安装脚本上，脚本已同步修好。
- **不允许尾随逗号**：.NET 配置提供程序接受尾随逗号，PS 5.1 的 `ConvertFrom-Json` 不接受。两侧都能接受的交集是不写尾随逗号，测试用默认选项的 `JsonDocument.Parse` 把这条钉住。
- **`launchSettings.json` 不加注释**：它是 `Properties/` 下的开发期启动配置（VS / `dotnet run` 使用），不参与运维配置，仓库内也是唯一没有 BOM 的 JSON 文件，本次保持原样。
- **注释写「边界」而不是复述键名**：例如 `MaxPendingRetryTasks` 注明建议不大于 `QueueCapacity`，`ShutdownDrainTimeoutMs` 注明应不小于 `RetryMaxDelayMs`，`MessageArchiveThreshold` 注明只提示不删除，`VacuumAfterCleanup` 注明大库耗时可观。
- **配置文件绑定产生的空字符串语义**：`"ApiKey": null` 绑定后 `WebOptions.ApiKey` 是 `""`，`Program` 的鉴权过滤器用 `IsNullOrEmpty` 判断，行为正确；测试按空字符串语义断言，不写 `Assert.Null`。

## 验证

- 脚本解析（Windows PowerShell 5.1，即脚本 `#Requires -Version 5.1` 的目标运行时）：用 `Parser::ParseFile` 校验两个脚本无语法错误，再取出其中的 `Read-RelayJsonConfig` 直接对真实 `appsettings.json` / `appsettings.Development.json` 断言 `Service.Name=MqttRelayService`、`Mqtt.TcpPort=1883`、`Web.Port=5000`、`Web.Enabled=True`、`AuditStorage.RetentionDays=30`，开发文件 `QueueCapacity=1000`、`Serilog:MinimumLevel:Default=Debug`。
- 剥离器边界用例：字符串内含 `//`、`/*b*/`、转义引号（`"he said \"//not a comment\" ok"`）、双反斜杠路径在剥离注释后逐字保持不变，块注释与行注释均被移除。
- `dotnet test`：183 个测试全部通过（改动前 177 个，本次新增 6 个）。
- 编码检查：新增/修改文件均为 UTF-8 with BOM；两个脚本换行保持 CRLF；`git diff` 仅含注释与脚本函数改动，无整文件换行抖动。

## 边界

- 只覆盖 `appsettings.json` 与 `appsettings.Development.json`；`.codex/`、`.reasonix/`、`Properties/launchSettings.json` 下的 JSON 不参与运维配置，未改动。
- 注释只说明当前实现，不承诺未实现的行为（例如 `Web` 节不描述 TLS、ACL，`AuditStorage` 节不描述归档导出）。
- 安装脚本仍只读取 `appsettings.json`，不读取环境覆盖文件：环境文件里的 `Service:Name` / `Mqtt:TcpPort` / `Web:Port` 不影响安装脚本写入的服务名与端口提示。
- 脚本的注释剥离针对 `appsettings.json` 这一份文件；若将来出现超出手写注释范围的 JSON 结构（例如内嵌含 `*/` 的未闭合块注释），解析仍会失败并回退默认值，此时安装日志中的 Warning 是唯一线索。
